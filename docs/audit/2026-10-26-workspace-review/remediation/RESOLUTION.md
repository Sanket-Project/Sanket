## Remaining limitations

- **Unexpected write during setup (disclosed):** while first wiring the fixture stack, a shell-launch quirk silently dropped the isolation environment, so for ~2 minutes (11:27–11:28 UTC) the backend ran on `backend/.env` defaults. Its default signal pipeline fetched public signals and inserted **479 global `trend_signals` rows** (tenant_id NULL) into `sanket_recovered_20261026` (the table previously had 0 rows), and wrote short-lived login-attempt counters to the dev Redis. No tenants, users, forecasts or recommendations changed. The launchers now assert isolation before starting. **Cleaned up on 2026-10-26 at the user's request:** the 479 rows (window 11:26–11:32 UTC, `tenant_id IS NULL`) were deleted in one transaction that first verified the count; `trend_signals` is back to 0 rows. The Redis login counters expire on their own.
- The dashboard forecast chart could not be shown live: the isolated stack deliberately blocks the ML service (it reads/writes its own database). `/api/v1/health` therefore reports `degraded` (503) on that stack, which surfaces a generic "Request failed with status code 503" toast — environmental, but the generic toast wording for a background health check is worth improving.
- `cache-probe.mjs` still returns A: it exercises TanStack's shared-client behaviour, which is unchanged. The fix ensures the app never shares a client across identities.
- The Financial page (`routers/financial.py`) still values an unknown unit cost as 0 — the same mechanism as F3, outside the 16 findings (ROI was fixed after review).
- Review minors not changed: decisions extend the last forecast week when lead + review exceeds the run (undisclosed), the current part-elapsed week counts in full, the confidence endpoint scores past weeks, Back/Forward restore may clamp on long lazily-loaded pages, simulator copy hard-codes the 14/30-day thresholds.
- Stale-with-timestamp display (show the last good value with its time when a refetch fails) was not built; failures show an explicit alert instead.
- The dashboard still generates a forecast on mount with `force_zero_shot` (initial-report P1 note) — not changed.
- No screen-reader session, full WCAG audit, or calibration experiment was run.
